# Data files (CSV, generated tables, ini, JSON, screenshots)

> Status: documented at commit 4db1d7d; last verified 2026-10-18. Audience: A and B.

## Purpose

This page lists every data file in the repo that is not source code or a script. For each file it gives the format, the size, who reads it or writes it, and what is missing or stale. Scripts are on [tools-reference.md](tools-reference.md). The meaning of the settings in the ini file is on the settings pages.

No game assets are in the repo. The only texture data is a list of names and three yes or no flags (`data/texture_tags.csv`). The `.gitignore` blocks binary and game files, including `*.dll`, `*.exe`, `*.zip`, `*.png`, `*.dds`, `*.rkv`, `*.log`, and `*.key` (`.gitignore:1-23`).

### Where the mod writes its files at run time

These are the files the renderer, launcher and installer create. Nothing is sent anywhere.

| File or folder | Written by | Notes |
|---|---|---|
| `<game folder>\tyrender.log` | DLL | Opened with `"w"` at each start, so the previous log is replaced (`src/tyrender.cpp:708`). |
| `<game folder>\tyrender\logs\TYHD_report_<time>_<build>.txt` | DLL (session report) | One per game start. `[report] KeepFiles` (default 10) limits how many are kept (`src/default_tyrender.ini:96`, `src/sesslog.inl:2`, `:259-262`). |
| `<game folder>\Screenshots\` | DLL (F11 A/B) | Created on first capture (`src/abshot.inl:3`, `:92`). |
| `<game folder>\tyrender\snaps\` | DLL | Snapshot folder (`src/tyrender.cpp:524`). |
| `<game folder>\tyrender\dump\`, `tyrender\override\` | DLL | Shader dump and override folders, created at start (`src/tyrender.cpp:710-711`). |
| `<game folder>\tyrender\reload` | launcher or user | Empty flag file. The DLL deletes it after reloading (`src/tyrender.cpp:597-598`). |
| `<game folder>\tyrender\cam.txt` | user | Debug camera offset (`src/debugcam.inl:1-3`). |
| `<game folder>\tyrender\install.log`, `install.ini`, `backup\` | installer | See the installer page. |
| `<game folder>\TyOutputLog.txt` | the game, not the mod | Read by the test scripts (`tools/ty_play.ps1:6`). |

Hand-written flag files (`ao_off`, `cap.req`, and others) are on [hotkeys-and-files.md](hotkeys-and-files.md).

### `data/texture_tags.csv`

1. Line 1 is the header: `path (relative to PC_External folder)`, `name (file name)`, `emissive`, `transparent`, `character`. The header also describes what yes and no mean for each flag (`data/texture_tags.csv:1`).
2. The file has 1934 non-blank lines, so 1933 data rows (checked by counting non-blank lines).
3. Each row has five fields. The three flags are `yes` or `no`.
4. The generator reads the owner's copy, not this file: `src/gen_tex_tags.ps1:4` imports `<owner root>\RESEARCH\recording\texture_tags.csv`. The repo copy is mirrored from that folder by `tools/repo_sync.ps1:17`.
5. At run time, a file named `tyrender\texture_tags.csv` in the game folder overrides the embedded flags by name (`src/tex.inl:5`, `:83`). Use this for a local test without rebuilding.

Whether the repo copy matches the owner's copy is not known (NI-D1).

### `src/tex_tags.inc`

1. Line 1 says `generated by gen_tex_tags.ps1 - do not edit` (`src/tex_tags.inc:1`).
2. `kTagNames[]` holds 2423 entries. Each has a lower-case file name and a flag byte (`src/tex_tags.inc:2-4`). The flag bits are: 1 known, 2 emissive, 4 transparent, 8 character (`src/gen_tex_tags.ps1:2`).
3. `kRkvDds[]` maps offsets and sizes in `Data_PC.rkv` to indexes into `kTagNames` (`src/gen_tex_tags.ps1:3`).
4. Names that are not in the CSV get flag 0 (`src/gen_tex_tags.ps1:2`). The generator also reads `<owner root>\RESEARCH\rkv_index\Data_PC.csv` (`src/gen_tex_tags.ps1:10`). That index is not in the repo.

The two counts differ, and that is expected from the generator: 1933 CSV rows and 2423 names, where the extra names are archive entries that carry no flags. This explanation is inferred from the generator comments and was not re-run.

### `src/default_tyrender.ini`

1. The file has 115 lines and 65 keys across 17 sections: `[ao] [gi] [lod] [atmos] [tess] [shadows] [post] [pbr] [spill] [decal] [light] [fog] [report] [shots] [portability] [emit] [overlay]`.
2. It is compiled into the launcher and the installer as resource 2 or 4 (`src/build.ps1:17`, `:27`). The launcher writes it to disk only when `tyrender.ini` is missing (`src/TYLauncher.c:49`). The installer merges its keys into an existing file (`src/installer/common.inc:125-141`).
3. Keys absent from this file use the in-code default. Those defaults are on the settings pages, and some differ from the launcher's slider defaults (see [launcher.md](launcher.md), Discrepancies).
4. The header on line 1 says the file is the Medium preset and gives "about 80 fps" (`src/default_tyrender.ini:1`). No measurement in the repo gives 80 fps for this preset. `docs/results/preset_matrix.md` gives 92 fps for Medium (its `fps` column, row "Medium"). `docs/RESUME.md:57` and `docs/PLAN_EXEC.md:53` both record this header as a known text fix.
5. The launcher writes these keys on every save, and the shipped file does not contain them. The DLL uses its in-code defaults for them until the first save from the launcher. The absent keys are: `[post] Contrast`, `[post] Sharpen`, `[ao] Strength`, `[ao] WideStrength`, `[gi] Strength`, `[shadows] Strength`, `[shadows] GrassStrength`, `[fog] Amount`, `[fog] Distance`, `[atmos] SunIntensity`, `[tess] ReliefDepth`. This was checked by searching the file for each key.
6. `[overlay] Key=F10` is set in the shipped file (line 115). The in-code default is `0` (`src/overlay.inl:43`), so the shipped file is what turns the overlay on for a Setup install.

### `docs/todo.json`

1. The file is a JSON array of 83 items with ids `T00` to `T92` (counted from the file).
2. Each item has 15 fields: `id`, `title`, `kind`, `status`, `deps`, `needs_game`, `command`, `fail_if`, `est_tokens`, `task`, `notes`, `attempts`, `started`, `finished`, `result`.
3. `kind` values and counts: `lead` 24, `auto` 28, `agent` 27, `director` 3, `user` 1.
4. `status` values and counts: `done` 65, `open` 17, `dropped` 1.
5. The runner reads the owner's copy from `<owner root>\RESEARCH\todo.json` (`tools/todo_runner.ps1:1-2`). The repo copy is a snapshot. The item fields and their meanings are described in the header of `tools/todo_runner.ps1:1-8`.
6. The item titles and results are work notes. Summaries and mapping to issue numbers are on [history-and-timeline.md](../decisions/history-and-timeline.md) (Ch13).

### Playtest request queue (`tools/playtest/requests/`)

1. The template is `TEMPLATE.json`. Its fields are `id`, `status`, `priority`, `requester` (`issue`, `thread`), `question`, `variants`, `checks`, and `report` (`tools/playtest/requests/TEMPLATE.json:1-24`).
2. Each check has `id`, `kind`, `variants`, `pattern`, `mustMatch`, `baseline`, `limit`, `pass`, `decides`, and `next`.
3. The template lists the kinds `log`, `flicker`, `overlay`, `boot`, and `manual` (`TEMPLATE.json:13`). The runner also supports `tyflicker` (`tools/playtest/autoplaytest.ps1:215`), and `docs/AUTOPLAYTEST.md:134` lists it. The template is out of date (Discrepancies).
4. The folder holds eight requests (`req-79` to `req-86`), a README, the template, and `f11_true_off.md`, which is a spec and not run (`f11_true_off.md:4`).
5. `README.md` in that folder says finished requests move to `done/` and blocked ones go to `BACKLOG.md`. Neither folder is in the repo.

### Playtest plans (`tools/playtest/plans/`)

1. `current_run.json` has a `name`, a `purpose`, and a list of `checks`. Each check has `id`, `kind`, `variants`, `issue`, `decides`, `pass`, and `next` (`tools/playtest/plans/current_run.json:1-10`).
2. `next_monitor.json` uses the same shape and includes the `tyflicker` kind (`next_monitor.json:7`).
3. `build_plan.ps1` merges pending requests into one plan (`tools/playtest/build_plan.ps1:1-7`).

### Test ini (`tools/test_ini/emit_portal_test.ini`)

1. The file is a full settings file for the emitter test. Its line 1 has the same "Medium, about 80 fps" header as the default ini (`tools/test_ini/emit_portal_test.ini:1`). See point 4 of `src/default_tyrender.ini` above.
2. It is used by a playtest run and is not read by the build.

### Screenshots and captures

- `docs/ab/` holds 32 JPEG files. The names follow `<fog|nofog>_<n>_<scene>[_crop]_<on|off>.jpg`. Each scene has a full frame and a crop, in an on and off pair. The naming is used by the A/B process (see [ab-captures.md](../guides/ab-captures.md)).
- `docs/playtest_frames/` holds JPEG frames and a `data/` folder with six CSV files.

### Results, recordings, and agent files

- `docs/results/` has 11 Markdown files: three DIRECTION checkpoints, `R6_config_diff.md`, `VERDICTS.md`, `balanced_result.md`, `cost_table.md`, `g1_gate.md`, `g1_gate_prev_3EE5DA28A7.md`, `merge_log.md`, and `preset_matrix.md`. These are measurement outputs and decision records.
- `docs/recording/` holds 4 Markdown findings files, `INDEX.md`, and 6 `.txt` files. The `.txt` files are voice transcripts. This page does not quote them. The copy step includes both `.md` and `.txt` files from the owner's folder (`tools/repo_sync.ps1:15-16`).
- `docs/agent-tasks/` holds `BRIEFING.md`, `_common.md`, and 21 task files.

## Settings

Not applicable. This page does not define keys. For the ini file, the key list and defaults are on the settings pages. The shipped values are in `src/default_tyrender.ini`.

## Cost

Not applicable. Data files have no run-time cost apart from the texture tag table, which is compiled into the DLL. The generated file is about 121 KB (`wc -c`).

## Limits

- `data/texture_tags.csv` is a user list, not a verified one. An unlabelled name gets no flags.
- `src/tex_tags.inc` cannot be rebuilt from the repo alone. It needs the owner's `RESEARCH` folder and `rkv_index` (NI-D2, N-17).
- The default ini is partial. A key that is not in it gets its code default, and these are not always the same as the launcher's values (see [launcher.md](launcher.md)).
- The installer adds only keys that are in the bundled ini (`src/installer/common.inc:125-141`). A new key added in code is not added to an existing user file by Setup.
- Playtest and request folders named in the README (`done/`, `BACKLOG.md`) are not in the repo.
- The `.gitignore` does not stop `.txt` files, so transcripts can be committed (`.gitignore` has no `*.txt` rule).

## Known issues

- The header claim "about 80 fps" in `src/default_tyrender.ini:1` and `tools/test_ini/emit_portal_test.ini:1` does not match `docs/results/preset_matrix.md` (92 fps). Known text fix in `docs/PLAN_EXEC.md:53`.
- The request template does not list the `tyflicker` kind that the runner and the plan use (`TEMPLATE.json:13`; `next_monitor.json:7`).
- `tools/presets.ps1` lists a different Medium preset from the launcher and the shipped ini (see [presets.md](presets.md)).

## How to verify

1. Count the texture rows: `grep -c "[^[:space:]]" data/texture_tags.csv`. The result should be 1934 (header included).
2. Count the ini keys: `grep -cE "^[A-Za-z][A-Za-z0-9_]*=" src/default_tyrender.ini`. The result should be 65.
3. Check the todo counts: `grep -c '"id"' docs/todo.json` should give 83.
4. Check the overlay default in code: `grep -n '"overlay", "Key"' src/overlay.inl`. The default should be `"0"`.
5. Check the tag override: put a `texture_tags.csv` in `tyrender\`, change one flag, and run with `[tex] LogUnknown=1` (see [log-and-error-messages.md](log-and-error-messages.md)).

## Discrepancies

- `src/default_tyrender.ini:1` says Medium is "about 80 fps". `docs/results/preset_matrix.md` gives 92 fps for Medium. The repo has no source for 80.
- `tools/playtest/requests/TEMPLATE.json:13` lists five kinds. The runner (`tools/playtest/autoplaytest.ps1:215`) and `docs/AUTOPLAYTEST.md:134` also support `tyflicker`.
- `src/package.ps1:9` comments that the shipped ini is the "Balanced" preset (C1 in `tools/presets.ps1`). The ini header calls it Medium (`src/default_tyrender.ini:1`). These are two names for the same settings. The launcher calls it Medium (`src/launcher_ui.inc:216-220`).
- `src/tex_tags.inc` has 2423 names, and the CSV has 1933 rows. The generator explains this only in comments (see above).
- First pass (`LAUNCHER.md`) does not list these data files. Nothing to correct there.
