1. Read `C:\CLAUDE\RESEARCH\GOAL.md` (what we are building and what "done" means) and `C:\CLAUDE\RESEARCH\agents\BRIEFING.md` (project, build, harness). Your private source copy is `C:\CLAUDE\SRC\agents\<name>\`; never edit the master `C:\CLAUDE\SRC\tyrender\` or another agent's folder.
2. **You may be cut off at any time** (usage limits). So: after every meaningful step call `powershell -NoProfile -File C:\CLAUDE\TOOLS\steplog.ps1 -Agent <name> -Msg "<what happened + numbers>" -Files "<changed files>"`, and keep `REPORT.md` in your folder current (not only at the end). On start, read your own step log `C:\CLAUDE\RESEARCH\sessions\2026-10-12_session5\agents\<name>.md` first and continue; do not redo finished work.
3. **Token discipline** (the lead is watching usage): read only what you need; do not paste big files into replies; keep replies to a few lines; do not re-read files you just wrote. Do not babysit the game: use the programmatic tools and read their output files.
   - A/B and measurements: `powershell -NoProfile -File C:\CLAUDE\TOOLS\suite.ps1 -Name <yourname>_<tag> -Dll <your dll> -AB "A=<ini>;B=<ini>"` runs an in-session A/B (same camera/session) over 5 standard views with GPU timers and writes `C:\CLAUDE\RESEARCH\results\<Name>\sheet.png` (rows = views, columns = variants), `ty_strip.png` (Ty crop per variant), `manifest.json`. View the sheet/strip (2 images) instead of many full-size PNGs. Only live-reloadable ini keys can differ between variants; for restart-only switches use separate suite runs. Ini fixtures: `C:\CLAUDE\RESEARCH\results\inis\`.
   - The harness runs one game at a time (global lock) and needs the focus keeper (started by the lead). If a run reports FOCUS LOST / gameplay not reached repeatedly, stop and log it; do not loop.
   - Flicker / stability: `powershell -NoProfile -File C:\CLAUDE\TOOLS\motion.ps1 -Name <yourname>_mo -Dll <dll> -AB "off=<ini>;a=<ini>;b=<ini>" [-Step 0.12 -Frames 16 -Reps 2]` (smooth camera yaw, temporal 2nd difference, result `results\<Name>\motion.md`; acceptance: each pass <= 1.5x the `off` variant) and `flicker.ps1 -Name <n> -Dll <dll> -AB "..."` (static camera). Both run at high fps and ignore Ty; judge shadow-edge or low-fps flicker by construction plus images, say so in the report.
   - Environment variables for the harness (set in your shell before the call): `TY_SLOT=2` (boot save slot 2, Billabong; default slot 1), `TY_SETTLE=<s>` (wait after gameplay is reached), `TY_CAMWAIT=<s>` (wait after each camera move). Other tools: `abshots.ps1` (community A/B shots), `launcher_shot.ps1` (launcher UI screenshot), `g1_gate.ps1` (lead's release gate; do not run it).
   - Debug GL leak detector: `[debug] StateGuard=1` logs `[state] LEAK after <pass>` lines to tyrender.log (copy in the suite output dir).

Never trust a cost number that was not measured with the GPU timers on the same scene.
